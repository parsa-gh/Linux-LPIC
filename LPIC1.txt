Filesystem : a part of linux kernel -- any partition we make has some binary codes which is hard to read for humans, also files contain metadata, so we cannot easily find out which piece of binary codes are for metadata, origin file, etc -- file system does that for us
some common FSs : NTFS, FAT, [X]EXT, [X]ReiserFS, [X]XFS, [X]JFS, VMFS, [X]BtrFS(Read butterFS), etc. -- FSs that can be host of linux are marked with [X].

EXT(Extended File System) : Got 4 versions till middle of 2026 - EXT4: default file system for linux -- compatible with SSD 
Benefits :
- 1. Supports all characters for file names except NULL, and '/'
- 2. EXT3 is convertable to EXT4
- 3. Advanced options like : 1. delayed allocation - 2.directory indexing - 3.extend & defragmentation
- 4. infinite sub-directories
- 5. nanosecond timestamp (EXT1) had some problem with timestamps.
- 6. Predefined for extended files
- 7. Multiple block allocation
--
Disadvantages :
- 1. Data security is NOT supported (CIA)
- 2. Complicated snapshots on different volumes
- 3. More disk space is needed.


swap : cloning some process which are on logical memory to a new partition/file and uses free space that just cloned, and processes that dumped(cloned) to a partition, will be inactive till we need it again so we swap it into logical memory
virtual memory = RAM + Swap 
!! BUT !! swap space is not acting as memory, its job is to only make some free space to new processes so they could be run


/dev/ : directory that linux recognize hardware files (Disk)
/dev/sda ==> for sata/scsi disks linux name them "sd" and per each, uses alphabet => 2 scsi disks: /dev/sda && /dev/sdb --- partitions on each disk will be count with numbers => 1 scsi disk with 3 partition : /dev/sda /dev/sda2 /dev/sda3

Bash shell : default shell on most linux kernels -- 

user@pc:~[$/#] : if $ == you are normal user and no root privilages, if # == then user is superuser(root) -- 

Internal commands : like cd, pwd, echo, etc. => they're compiled into bash by default
External commands : for external commands a program must be written, compiled and introduced to bash, then bash recognizes it and we can use it ( path ) -- to see which directories bash checks for this, execute [ echo $PATH ]
printenv command : list of external commands that are available in memory at the moment

Meta characters : 
; ==> seperates commands from each other 
Ex) date ; date  / will be executed twice
&& : command seperator BUT if status code of first command is zero(which means OK in linux) then second commmand is executed
Ex) cal && cal
|| : executes second command if status code of first command is anything but zero (which means UNSUCCESSFUL in linux)
\ : usable for other meta chars when needed to use them in Cli, for example executing ; will not work out until we use this trick : \; , it says to bash that next char is not going to execute as a command
whenever we execute a command, bash will take that and execute it with a process. process can show a msg (STDOUT) anytime it wants. by default it shows that msg on screen, but with a special char called " greater than (>)" it understands that ought to send msg to a file.
Ex) date > out.txt
Ex) ping 127.0.0.1 -c3 > out.txt

STDIN(standard input): if a program needa argumans or what so ever, bash will connect your keyboard directly to that process
giving input data from a file with (<)
